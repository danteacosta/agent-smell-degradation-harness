# Fresh Kanboard search-example decontamination pilot, qualified successor v4

The prior full-document old arm contained the corrected `assignee:me` token in another section. The first derived-excerpt v3 collection also retained an `assignee:bob` browser check that the excerpt did not specify, making all six primary comparisons unknown. This fresh v4 **derived excerpt** pilot keeps only the exact historical example and surrounding introduction; its browser journeys check `assignee:me` for two users plus the ordinary title-word baseline. It is not a replacement for v2 or v3.

Acceptance contract: given a source-grounded old or corrected excerpt, a model registers one search callback without seeing the browser HTML, oracle, expected query, or historical parser. When a user searches for the current user's tasks in the reconstructed browser, the callback should return only that user's task IDs. Ordinary title search should still work. A wrong implementation, missing control, JavaScript error, malformed report or provider failure must remain distinct from a target success. The oracle is independently grounded in the pinned historical Kanboard parser and visible search UI.

Before generation: verify that the old excerpt has no corrected token elsewhere; verify that the common prompt has no target keyword or HTML; check the unchanged historical license/source and executable/browser-image hashes; qualify reference, wrong-target, wrong-title, mixed, missing, duplicate and runtime-error controls; freeze the two source excerpts, UI, runner, seed, 12-position schedule, prompts and receipts. The only arm difference is the `assigne:me` → `assignee:me` token in the historical example. Two saved-session Codex model aliases, three repetitions per arm, randomized order, single attempt per position, and separate generation contexts.

After all generation ends, observe each artifact in an isolated browser context. A pair is improved only for an old target-only failure against a new pass; non-target/mixed/browser/provider failures are unknown, never silently omitted. Treat the requirement as one inferential unit. This reconstructed interface does not prove a full Kanboard app bug, ordinal quality, H1 or H2. No old packet or outcome is edited.
