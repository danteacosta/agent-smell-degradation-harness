# E2E-first H1 expansion

The primary H1 endpoint now requires a user-visible interface. A planned slot
is admissible only when its generated artifact contains the tested interface,
the oracle acts in a real browser, and the target is observed from rendered UI
state with native screenshots. API/domain tests may support diagnosis but do
not turn an endpoint-only replica into an E2E result.

## Source screening

Of the 12 previously sampled intents, TodoMVC Mark all and Persistence have
qualified browser instruments. StrictDoc SRS-97 has a UI source obligation and
has now matched 21 authored browser controls; independent admission and prompt freeze remain pending. TodoMVC New todo has already been measured and remains a
historical result, not a new independent intent. StrictDoc SRS-47 and SRS-157
and CaSS DATA-011 retain their earlier deferrals. The three RealWorld API
endpoints and two CaSS API obligations are deferred from the **primary E2E
cohort** until an independently sourced UI requirement links a user action to
their outcome. Their API oracles may be retained as auxiliary controls.

This changes the provisional 144-generation, four-project design. Subject to admission, the current E2E-capable subset has three new intents in two projects:
3 × 3 arms × 2 model configurations × 3 repetitions = 54 planned generations.
This is not an adequate substitute for the proposed four-project expansion.
Before inference beyond these two projects, screen new projects with licensed,
pinned UI requirements and independent browser journeys. Do not recruit API
intents solely by adding a test-only wrapper screen.

## Acceptance and analysis

Each admitted intent has a pinned source/omission span, common public UI
contract, A/B/C prompts audited for leakage, a trusted browser oracle, valid
alternative controls, selective mutants, screenshot evidence and a frozen
runtime. Only then generate in isolated randomized contexts. Keep every
planned position, including invalid outputs, timeouts, source recovery, null
effects and unattempted slots. Compare within intent and then across projects;
replications remain nested within intents. H2 still requires a separate
project-level holdout and prospective pre-code signals.

The StrictDoc date case operationalizes generation as first render of a
standalone statistics view. Two private UTC clocks and fixture values test
whether a visible date tracks the event. Non-target statistics have explicit
neutral observation handles. This is a bounded UI replica, not upstream
StrictDoc compliance. A case failing the required rendered interface is invalid,
not evidence of the omitted obligation. If accepted date representations or
the event interpretation cannot be reviewed independently, defer the case
before any generation.

## Admission checkpoint — 2026-09-23

The independent source/prompt review accepted all three A/B/C bundles, but
endpoint review deferred Mark all and StrictDoc. Only persistence is accepted
for its bounded visible-restoration endpoint. See [admission and freeze](2026-09-23-e2e-admission-freeze.md).
The earlier 54-slot, two-project count is conditional history, not the current
admitted cohort. A persistence-only pilot has 18 positions in one project and
does not fulfill the cross-project expansion.
