# RealWorld comment Delete: prospective replication contract

The pinned RealWorld routing specification says the Delete comment action is shown only to the comment's author. The earlier v4 browser pilot made 18 A/B/C attempts and all three arms passed in both model configurations. This successor deliberately replicates that known null result; it is not an independent discovery case. The earlier v3 and v4 packets and review histories remain separate. The v4 page, runner, classifier, arms, source and license must match their earlier frozen hashes; only schedule identity, random seed and collector custody are new.

ATDD acceptance: before any new generation, verify the old v4 packet, its 11/11 authored-control qualification, 3/3 no-material-blocker adjudication, exact A/B/C prompt bytes and browser runtime. Freeze 18 fresh slots (A/B/C × Luna/Sol × three repetitions) with a new seed, a pinned Docker image, the authenticated Codex CLI executable and no API-key fallback. Run each slot in an isolated provider context, with no retry of an attempted slot. Evaluate all valid HTMLs after generation, including invalid, failed and unassessable outcomes in the denominator. Publish per-slot categories, hashes and paired browser evidence without replacing the older result.

BDD scenarios:

- Given author and other-viewer fixtures, when an A or B generated article page renders a comment, then Delete is visible only to its author and the comment remains visible to the other viewer.
- Given C omits the author-only condition, when the same browser journey runs, then a visible Delete action for the other viewer is a target failure; an absent comment or broken page is separately unassessable or non-target failure.
- Given a provider error, altered shell, browser error or missing screenshot, when results are classified, then the slot remains explicit and is never silently counted as a pass or defect.

The result is exploratory (`confirmatory_eligible: false`). Six comparisons in one obligation are nested repetitions, not six independent requirements. A null replication would strengthen the observation that this particular omission is often recovered in this scaffold; a positive contrast would show stochastic heterogeneity, not a general H1 effect. This work changes no existing reference or previously frozen result.
