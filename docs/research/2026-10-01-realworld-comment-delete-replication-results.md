# RealWorld comment Delete: second E2E run

The new RealWorld replication produced **18/18 valid HTML artifacts and 18/18 browser passes**. A, B and C each passed 3/3 on Luna and 3/3 on Sol. In particular, the six C outputs still showed Delete to the comment author and hid it from another signed-in viewer while preserving the comment. The earlier v4 run also had 18/18 passes, so this is a second observed tie for **one obligation in one project**. It does not support a degradation effect for this omission.

The source is the public RealWorld routing specification's “Delete comment button (only shown to comment's author)” clause. A and B state the author-only condition; C requests the Delete action without that condition. The exact v4 arms, source, license, fixed browser page, runner and classifier were hash-matched to the earlier private packet before the new run. The prior packet's 11/11 browser controls and independent 3/3 no-material-blocker adjudication were reverified. The new schedule used seed `2026100103`, two model configurations, three repetitions per arm and no retries or API-key fallback. All generations finished before browser evaluation. [Protocol](2026-10-01-realworld-comment-delete-replication-contract.md).

The 18 generated HTMLs contain only four distinct byte hashes. Every unique implementation, including those produced under C, checks `comment.author.username` against `app.viewer()` before adding the button. The fixed page exposes both values through its neutral API. This is **compatible with contextual recovery** of the omitted rule; this run does not isolate which cue caused the model to recover it. The six repetitions and two model configurations do not turn this into six independent requirements.

The [public per-slot summary](../../data/e2e-realworld-comment-delete/replication-20261001/summary.json) contains all 18 categories, HTML hashes, report hashes and screenshot hashes. This remains exploratory and outcome-aware: the earlier null was known when this replication was selected. It is useful negative evidence against a universal omission effect, not a confirmatory H1 estimate or an H2 test. A future information-boundary ablation would need a new freeze and a defensible interface that still lets the author-only rule be observed.
