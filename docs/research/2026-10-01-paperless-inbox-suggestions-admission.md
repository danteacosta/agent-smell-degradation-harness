# Paperless inbox suggestions: admission status

The public Paperless-ngx usage guide says an inbox-tagged document triggers an automatic suggestions request when opened. The proposed E2E measures that request and the visible suggestion returned by a fixed local service; it does not assess suggestion quality, acceptance/rejection, or the setting that changes the behavior to manual-only.

The first authored-control run exposed an oracular mistake: an empty `<ul>` was itself considered invisible, so a missing request became `interface_error`. That incomplete packet was preserved. A fixed-height suggestion area corrected the observability boundary before any generation. The versioned successor matched **12/12** expected browser categories in the pinned Chromium image: two correct implementations, missing/manual/fake/double requests, wrong document or suggestion, a wrong title, hidden controls, and a script error. The private qualification receipt is versioned `paperless-inbox-suggestions-qualification-20261001-v2`, SHA-256 `b891cea5c870836e32e2ec9f87c4847b8f8e39d3706ccd86dd4c2f05571e52a6`.

The independent pre-generation panel reviewed the exact public source excerpt, all three full prompts, fixed page, runner, classifier and authored-control outcomes. Astra, Sol and Luna returned **3/3 `NO_MATERIAL_BLOCKER`**. The frozen review request SHA-256 is `2fc6969b90a4f0347a904446d40f23d2f1d1da3525a62967fbbcbdffa79fb232`; the private review receipt SHA-256 is `8e196486c5618cf850113a2198e5c54f4a3b50095f765e3bfc5e70e0270a75c3`.

The admitted v1 collector made 18 attempts, producing 17 valid HTMLs and one invalid output. Its composite oracle classified all 17 valid pages as target failures. Inspecting generated A/B code and the browser reports exposed a false-positive rule: the models made the correct automatic request but appended Accept/Reject buttons inside each suggestion item, and the oracle compared the entire item text to the bare label. The v1 packet and its categories remain frozen. A separately identified browser-only diagnostic with a repaired label check reclassified the 17 existing HTMLs as A 5 pass + 1 invalid, B 6 pass, C 6 target-only failures. This diagnostic is not a new generation or a substitute for v1.

The repair was reproduced first by an authored valid suggestion with an Accept button failing the old oracle. The successor oracle ignores button text while reading the visible suggestion label and distinguished an altered label with the same button. It passed **14/14** versioned browser controls. The next collector uses a new seed and packet and requires a fresh exact-instrument review; it keeps the same A/B/C generator prompts and records the v1 and diagnostic receipts.

The packet was finalized with eight browser evaluations, one provider error and nine not-attempted slots. The original and diagnostic packets remain separate.

**Status: v1 composite classification invalid for scientific comparison; v2 partial because of provider capacity; v3 completed as a fresh 18-slot exploratory run.** The v3 instrument and prompts were byte-identical to the admitted v2 version. It used a new seed, linked both prior packets and the diagnostic, and produced A/B 6/6 passes each, C 4/6 target failures and 2/6 passes.
