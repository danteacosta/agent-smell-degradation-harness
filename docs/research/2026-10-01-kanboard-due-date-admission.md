# Kanboard due-date color: admission status

The public Kanboard `tasks.md` Due Date bullet combines two obligations: color overdue dates red and upcoming dates black on the board, and accept several input formats alongside a picker. This proposed browser endpoint measures **only the color subclause**. Its ISO input fixtures cannot establish compliance with the format or picker obligation.

Before any model generation, the authored-control qualification exercised 13 cases in the pinned Chromium image: 2 correct implementations, 4 color-rule mutants, 2 neutral-content mutants, 4 interface mutants, and 1 browser-error control. All 13 classifications matched their prior expectations. The private qualification packet verified 82/82 files; its receipt SHA-256 is `b1a8aa8a4f9d047848d1ad3a5bca213a782fdddb7d71bad23bacb3c754bfbab3`. This qualifies the instrument against authored controls, not the source mapping or any generator outcome.

The first exact-instrument LLM review returned two `NO_MATERIAL_BLOCKER` votes and one `DEFER`. The dissent identified the mismatch between an ISO-only color endpoint and a claim about the entire Due Date bullet. Its frozen request SHA-256 is `bd95d0c64197fa5ea8477a1b454d2e77af12ff59f7912663ea7de2de73b88842`. A second request, SHA-256 `1e6ba48f9be1ae3e97e64122f5b2c5257e9ddc206ac8bdaf7570f9b0cca7b623`, made the subclause boundary explicit. It returned one favorable vote and two `DEFER` votes: the browser measured the parent element's color rather than the text's color, and the common prompt did not define overdue/upcoming relative to the clock. All votes remain in their private packets.

The runner now measures the computed color of each visible text node, and the common prompt defines dates strictly before/after the current UTC day without supplying either color. Two new authored controls challenge parent/child color disagreement. The revised browser qualification matched **15/15** controls; its receipt SHA-256 is `14cc9dedab3f3215aca0191728acac2aa4fbfbd0744245f0cfe869c0001e0d90`. The blockers were painted text versus computed color (`-webkit-text-fill-color`, opacity and hidden descendants) and whether the A/B wording and added UTC-day semantics isolate the source rule. These are material methodological objections, not failed provider calls.

**Status: deferred; zero Kanboard generation calls.** The collector requires three favorable votes on the third request and matching hashes of the exact prompts, arms, page, runner, qualifier, and qualification receipt. That condition failed. After three rejected instrument versions, another CSS patch would compound the design problem. Reconsider the boundary: a fixed board renderer with model-generated date classification/color policy could keep a real browser E2E while giving the oracle a narrower, observable output. That would be a new instrument and selection version, not a repair of this frozen request. No missing vote can be inferred from technical qualification. If a successor is admitted, its 18-slot run remains exploratory (`confirmatory_eligible: false`) and must report invalid, unknown, tie, and target-only outcomes separately. Results from this single source subclause will not independently confirm H1.
